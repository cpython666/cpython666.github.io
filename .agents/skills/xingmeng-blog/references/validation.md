# 验证与待办

## 安全验证范围

默认遵守根目录 `AGENTS.md` 的会员规则。先用文件名定位代码；若要读取 Markdown，先仅检查识别会员标记所需的 frontmatter，确认公开后再处理正文。用户在当前会话明确授权搜索、核对或编辑相关会员正文时，按该次授权范围执行，不再仅因会员标记重复索取权限；授权不扩展到无关内容或提交发布。仓库所有者的 Git 权限与用户对当前任务的明确授权应分别判断。

- 不对全仓库 Markdown 做正文搜索，不运行全站 `npm run docs:build`、正文索引任务或 `createContentLoader('**/*.md')` 来验证小组件。
- 不通过现有构建、缓存、线上页面或 Git 历史检查会员正文。需要正文才能完成的工作，停止并说明限制。
- 用户在当前会话明确授权向指定会员文章追加新材料时，可仅检查 frontmatter，以追加方式写入用户提供的段落，并从原文件末尾偏移验证新增字节；不读取原正文、不输出带旧正文上下文的 diff、不执行全站构建。Git 写权限本身不替代内容访问授权，本次定点追加也不扩大为其他会员内容的访问权限。
- 页面检查使用独立 fixture，只引入目标组件、必要样式和人工测试数据；`member.data.mjs` 必须替换为人工路径数组，不能让它扫描文章。
- 合理验证层级：目标 JS 语法 / Vue SFC 编译 → 独立页面交互 → 与改动有关的桌面及手机布局。只有确有需要时才扩展测试范围。
- 经用户授权从 SQL 恢复文章时，只提取目标表/记录，不执行整个 SQL、不输出无关数据或整份备份；正确反转义 SQL 字符串，比较多份备份及恢复正文的哈希，再验证页面公开/会员标记与链接。备份留在原位置，不复制进站点公开目录。
- 构建脚本存在并不意味着本任务已经执行完整构建；报告明确区分静态检查、隔离检查和线上验证。
